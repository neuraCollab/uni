# LeetCode Solutions

A growing collection of solved interview problems, one markdown file per problem, focused on the *reasoning* behind a solution (pattern recognition, why it applies, common mistakes) rather than just the final code — the goal is interview readiness, not a code snippet archive.

## Convention
- One file per problem, named `kebab-case-problem-name.md` (e.g. `two-sum.md`, `longest-substring-without-repeating-characters.md`).
- Every file follows [`template.md`](template.md) — copy it as a starting point for a new problem.
- Cross-link the problem to the pattern(s) it exercises (e.g. `[Sliding Window](../patterns/sliding-window.md)`) and to the relevant data structure note if one applies (e.g. `[Heaps](../data-structures/heaps.md)`), rather than re-explaining the pattern inline — the pattern files are the source of truth for the general technique; a problem file is about *applying* it to one specific problem.
- Keep entries concise and cram-oriented: the point is fast recall before an interview, not a tutorial.
