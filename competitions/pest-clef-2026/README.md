# PestCLEF 2026: извлечение графа знаний о вредителях растений, только графовыми методами

Решение задачи [PestCLEF @ LifeCLEF 2026](https://www.kaggle.com/competitions/pest-clef-2026)
([страница задачи](https://www.imageclef.org/PestCLEF2026)). В решении нет нейросетей и нет обучаемых
классификаторов: сущности, отношения и события извлекаются операциями над графами знаний.

**Задача.** Из веб-документов о карантинных вредителях (корпус EPOP: 110 train / 55 dev / 82 test) нужно
извлечь граф знаний. Узлы — вредители, растения, переносчики, болезни, места, даты и пути распространения.
Таксоны привязаны к NCBI Taxonomy, места — к GeoNames, пути распространения — к OntoBiotope.
Рёбра — 7 бинарных отношений (`Located_in`, `Detected_on`, `Found_on`, `Causes`, `Expressed_by`,
`Dispersed_by`, `Vected_by`) и n-арные события. Привязка к тексту не обязательна, поэтому оценка ведётся
на уровне графа.

## Метод

```
  внешние графы знаний                         фоновый граф знаний (из train)
  GeoNames: город ⊂ регион ⊂ страна ⊂ континент   узлы: таксоны, места, болезни, даты
  NCBI Taxonomy: вид → род → царство              рёбра: Causes, Vected_by, Found_on, Located_in, ...
          │                                       alias: поверхностная форма → узел
          └───────────────┬───────────────────────────────┘
                          ▼
 текст ─► 1. сущности = узлы графа, найденные по его alias-рёбрам
          (место-кандидат принимается, только если граф помещает его внутрь места из того же документа)
                          ▼
          2. граф документа: сущность — предложение — соседнее предложение
             + рёбра фонового KG между сущностями документа
                          ▼
          3. отношение (r, h, t) = симметричный Personalized PageRank h↔t
             × априор ребра r(h, t) в фоновом KG × центральность h; схема типов из онтологии задачи
                          ▼
          4. n-арные события = максимальные клики графа отношений
             (только рёбра, концы которых соединены через общий узел-предложение)
```

### 1. Сущности: поиск и связывание по графу (`pestkg/kg.py`, `pestkg/ner.py`, `pestkg/resources.py`)

* Фоновый граф строится из разметки train. У каждого узла (NCBI-таксон, GeoNames-место,
  OntoBiotope-класс, дата или болезнь) есть **alias-рёбра** к его поверхностным формам. Варианты форм
  выводятся по графу таксономии (`Xylella fastidiosa` → `X. fastidiosa`) и по числу (ед./мн.).
* К фоновому графу подключаются подграфы **GeoNames** (иерархия «город → ADM2 → ADM1 → страна →
  континент») и **NCBI Taxonomy** (тип неизвестного таксона определяется по его предку: Viridiplantae →
  растение, Hemiptera → переносчик и т. д.).
* Поиск — самое длинное совпадение по префиксному дереву alias-рёбер. На alias-ребре хранится
  статистика «сколько раз форма встретилась в тексте и сколько раз была размечена», и мелькающие
  формы отсекаются по этой доле.
* **Разрешение по иерархии мест.** Небольшой город или район принимается, только если путь `part_of`
  ведёт от него к месту, уже упомянутому в документе (`Limeira → São Paulo → Brazil`). Тот же путь
  выбирает правильный из одноимённых GeoNames-узлов.
* Аббревиатура вида «fall armyworm (FAW)» получает узел полной формы. Узлы для дат и названий болезней,
  которых нет ни в одной онтологии, создаются по текстовым шаблонам. Это единственная не-графовая
  часть решения: она только порождает узлы, ничего не связывает.

### 2–3. Отношения: случайные блуждания по графу (`pestkg/graph_re.py`)

Для документа строится взвешенный граф. Его узлы — сущности документа и предложения, рёбра такие:
сущность — предложение, где она упомянута; предложение — следующее предложение; сущность — сущность,
если фоновый KG уже их связывает (вес `w_kg · log(1 + число документов)`); место — место, если одно
вложено в другое.

Кандидат `(r, h, t)` допускается схемой типов отношения `r` и оценивается так:

    score = sqrt(PPR_h(t) · PPR_t(h)) · |V|  ×  (1 + kg_prior · log(1 + #док. с ребром r(h,t) в KG))
                                             ×  центральность(h)^c

Все PPR-векторы документа получаются одним обращением матрицы `(1-d)(I - d·Pᵀ)⁻¹`.
Центральность — PageRank головы относительно лучшего узла её типа: главный вредитель документа
связан с большинством упомянутых мест.

Обучаемой модели нет. `fit` перебирает по сетке 6 параметров графа (затухание, веса рёбер, априор,
центральность) и подбирает по одному порогу на отношение. Подбор идёт с **кросс-фиттингом**: для
каждого документа train сущности и фоновый граф строятся *без* этого документа, как на тесте.
Dev в подборе не участвует.

### 4. События: клики (`pestkg/events.py`)

На разметке train+dev 88% многоаргументных событий — клики графа бинарных отношений, а 83% событий
в точности совпадают с максимальной кликой. Поэтому событие — это максимальная клика графа принятых
отношений. Берутся только рёбра, концы которых соединены путём «сущность — предложение — сущность»,
то есть встречаются в одном предложении. Это ограничение подняло F1 событий с 0.23 до 0.28. Порог для
рёбер событий подбирается так же, на train.

## Результаты на dev

Модель подобрана на train. Метрика — micro P/R/F1 по узлам и тройкам графа `(relation, head_id, tail_id)`.
Идентификатор узла — NCBI/GeoNames/OntoBiotope id, а для дат и болезней — нормализованный текст.
Событие засчитывается только при точном совпадении множества `(роль, узел)`.

| уровень | P | R | F1 |
|---|---|---|---|
| упоминания (span + тип) | 0.718 | 0.727 | 0.722 |
| узлы графа | 0.777 | 0.735 | 0.755 |
| **отношения** | 0.479 | 0.516 | **0.497** |
| **n-арные события** | 0.311 | 0.254 | **0.280** |
| *отношения на эталонных сущностях (верхняя граница шагов 2–4)* | 0.610 | 0.694 | 0.649 |
| *события на эталонных сущностях* | 0.464 | 0.373 | 0.413 |

Вклад графовых компонентов (F1 на dev; на каждой строке параметры заново подобраны на train):

| вариант | отношения | события |
|---|---|---|
| только граф документа (PPR по сущностям и предложениям) | 0.389 | 0.227 |
| + рёбра фонового KG в блуждании | 0.492 | 0.282 |
| + иерархия мест в блуждании | 0.492 | 0.282 |
| + априор ребра того же отношения из фонового KG | 0.494 | 0.289 |
| + центральность головы | 0.497 | 0.280 |

Распознавание сущностей (F1 по узлам): словарь только из train — 0.684; с подграфами
GeoNames/NCBI и разрешением мест по иерархии — 0.726; с шаблонами дат и болезней — 0.755.

Больше всего дают рёбра фонового графа знаний: F1 отношений растёт с 0.39 до 0.49. Главное узкое
место — сущности: около 29% эталонных троек теряются, потому что не найден хотя бы один узел.

Для сравнения я пробовал варианты с машинным обучением, в решение они не входят. Градиентный бустинг
на текстовых и графовых признаках давал 0.545 / 0.323, BioBERT-NER на GPU — 0.533 / 0.309. Чисто
графовое решение отстаёт на ~0.05 F1, но в нём нет обучаемой модели.

## Запуск

```bash
pip install -r requirements.txt     # numpy, networkx
python download_data.py      # EPOP с Recherche Data Gouv, GeoNames, NCBI taxdump (~80 МБ); кэш подграфов
python run.py dev            # подбор на train, оценка на dev
python run.py dev --gold-entities   # шаги 2–4 на эталонных сущностях
python run.py test           # подбор на train+dev, предсказания для test в outputs/test/
```

Всё работает на CPU, один прогон занимает около 20 секунд.

В `outputs/test/` появляются:

* `relations.csv`: тройки графа `doc_id, relation, head_type, head_id, head_text, tail_type, tail_id, tail_text, score`;
* `events.csv`: n-арные события, аргументы в JSON `{роль: {id, text}}`;
* `a2/*.a2`: предсказания в формате BioNLP-ST (как исходная разметка EPOP), с привязкой к упоминаниям;
* `kg/kg_triples.tsv`, `kg/kg_nodes.json`: фоновый граф знаний из train+dev вместе с иерархией мест.

> Формат сабмита Kaggle (`sample_submission.csv`) без авторизации недоступен, поэтому `relations.csv`
> и `events.csv` — «сырые» таблицы графа. Под колонки соревнования их переводит `run.py::write_submission`.

## Структура

```
pestkg/
  brat.py       чтение/запись BioNLP-ST (.txt/.a1/.a2), схема ролей
  text.py       токенизация, предложения, ключи узлов
  kg.py         фоновый граф знаний: alias-рёбра, рёбра отношений, иерархия мест, экспорт
  resources.py  подграфы GeoNames и NCBI Taxonomy (фильтр по n-граммам корпуса)
  ner.py        поиск и связывание сущностей по alias-рёбрам графа, разрешение мест по иерархии
  relations.py  схема отношений (онтология), граф сущностей документа
  graph_re.py   граф документа + фоновый KG, Personalized PageRank, пороги
  events.py     события как максимальные клики
  pipeline.py   подбор параметров с кросс-фиттингом, предсказание
  evaluate.py   метрики на уровне графа
run.py, download_data.py
```

## Что можно улучшить (оставаясь в графовых методах)

* Вложения графа знаний (TransE/RotatE на фоновом KG + GeoNames + NCBI) как более гладкий априор
  ребра вместо подсчёта документов, чтобы обобщать на пары, не встречавшиеся в train.
* Путевые правила в духе AMIE/AnyBURL: например, `Causes(p, d) ∧ Found_on(p, x) ⇒ Expressed_by(d, x)`.
* Транзитивный вывод по иерархии мест для `Located_in`, если разметка EPOP его поддерживает.
