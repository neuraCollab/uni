# PestCLEF 2026: извлечение графа знаний о вредителях растений

Решение задачи [PestCLEF @ LifeCLEF 2026](https://www.kaggle.com/competitions/pest-clef-2026)
([страница задачи](https://www.imageclef.org/PestCLEF2026)) на основе графов знаний.

**Задача.** Из веб-документов о карантинных вредителях (корпус EPOP: 110 train / 55 dev / 82 test)
нужно извлечь граф знаний. Узлы графа — вредители, растения, переносчики, болезни, места, даты и пути распространения.
Таксоны привязаны к NCBI Taxonomy, места — к GeoNames, пути распространения — к OntoBiotope.
Рёбра — 7 бинарных отношений (`Located_in`, `Detected_on`, `Found_on`, `Causes`, `Expressed_by`,
`Dispersed_by`, `Vected_by`) и n-арные события (`Organisme_nuisible`, `Plante`, `Lieu`, `Date`, …).
Привязка к позициям в тексте не обязательна, поэтому оценка ведётся на уровне графа.

## Идея: граф знаний используется на каждом шаге

```
           внешние графы                        фоновый граф из train
   GeoNames (страна ⊃ регион ⊃ город)      (pest -Causes-> disease, pest -Vected_by-> vector, ...)
   NCBI Taxonomy (вид → род → царство)                     │
                 │                                         │
                 ▼                                         ▼
 текст ──► 1. NER + entity linking по словарю графа ──► 2. граф документа ──► 3. классификатор рёбер
           (+ контекстное разрешение мест по иерархии)   (узел = сущность,    (текстовые + графовые признаки)
                                                          а не упоминание)              │
                                                                                         ▼
                                                     4. n-арные события = клики графа отношений
```

1. **Распознавание и связывание сущностей** (`pestkg/ner.py`, `pestkg/kg.py`). Используется словарь
   из рёбер `alias` графа: поверхностные формы из train, их варианты (`Xylella fastidiosa` → `X. fastidiosa`,
   единственное/множественное число), а также имена из GeoNames и NCBI. Для каждой формы считается
   априорная вероятность того, что она размечена, когда встречается в тексте. Мелкие места (города, ADM2)
   принимаются, только если граф помещает их внутрь места, уже упомянутого в документе
   (`Limeira → São Paulo → Brazil`), и это же разрешает неоднозначность. Даты и новые названия болезней
   находятся шаблонами, аббревиатуры вида «fall armyworm (FAW)» наследуют узел полной формы.
2. **Граф документа** (`pestkg/relations.py`). Все упоминания одного таксона или места сливаются в один узел.
   Кандидаты в рёбра — пары узлов, чьи типы подходят под сигнатуру отношения.
3. **Классификация рёбер.** Используется HistGradientBoosting на двух группах признаков:
   * текстовые: число общих предложений, расстояние, слова-подсказки между упоминаниями, «ближайший узел
     своего типа», значимость узла в документе (частота, ранг, заголовок);
   * графовые: есть ли такое ребро в фоновом графе и сколько документов его подтверждают, степень
     узлов, число 2-хоповых путей между узлами, связан ли вредитель в графе с местом, которое
     содержит данное место или содержится в нём (иерархия GeoNames).

   Обучение идёт с **кросс-фиттингом**: признаки для документа обучающей выборки строятся по графу,
   собранному *без* этого документа, иначе графовые признаки «подсматривают» ответ. Те же фолды дают
   out-of-fold скоры, по которым подбирается порог для каждого отношения. Dev для подбора не используется.
4. **N-арные события** (`pestkg/events.py`). Наблюдение на разметке train+dev: 88% многоаргументных
   событий — это клики графа бинарных отношений (все пары аргументов связаны), 83% событий в точности
   совпадают с максимальными кликами. Поэтому события строятся как клики графа отношений, а отдельный
   классификатор оценивает каждую клику: размер, роли, мин./средний вес рёбер, максимальность, общие
   предложения.

## Результаты на dev (обучение на train, пороги подобраны out-of-fold на train)

Метрика — micro P/R/F1 по узлам и тройкам графа: `(relation, head_id, tail_id)`. Идентификатор узла —
NCBI/GeoNames/OntoBiotope id, а для дат и болезней без онтологии — нормализованный текст.
Для событий требуется точное совпадение множества `(роль, узел)`.

| уровень | P | R | F1 |
|---|---|---|---|
| упоминания (span + тип) | 0.718 | 0.727 | 0.722 |
| узлы графа | 0.777 | 0.735 | 0.755 |
| **отношения** | 0.571 | 0.521 | **0.545** |
| **n-арные события** | 0.348 | 0.301 | **0.323** |
| *отношения на эталонных сущностях (верхняя граница RE)* | 0.702 | 0.787 | 0.742 |
| *события на эталонных сущностях* | 0.455 | 0.514 | 0.483 |

Абляции (F1 по отношениям / событиям):

| вариант | отношения | события |
|---|---|---|
| только словарь из train | 0.451 | 0.269 |
| + GeoNames/NCBI и контекстное разрешение мест | 0.501 | 0.271 |
| + шаблоны дат и болезней, OOF-пороги, аугментация эталонными сущностями | 0.545 | 0.267 |
| + обученный скорер клик-событий | 0.545 | 0.323 |

Главное узкое место — NER: 29% эталонных троек теряются, потому что не найден хотя бы один узел.
На эталонных сущностях F1 по отношениям сразу вырастает до 0.74.

## Запуск

```bash
pip install -r requirements.txt
python download_data.py      # EPOP (тексты + разметка) с Recherche Data Gouv, GeoNames, NCBI taxdump (~80 МБ)
python run.py dev            # train → dev, отчёт по метрикам
python run.py dev --gold-entities   # RE/события на эталонных сущностях
python run.py test           # train+dev → test, файлы в outputs/test/
```

Всё работает на CPU, `run.py test` выполняется примерно за 15 с.

В `outputs/test/` появляются:

* `relations.csv`: тройки графа `doc_id, relation, head_type, head_id, head_text, tail_type, tail_id, tail_text, score`;
* `events.csv`: n-арные события, аргументы в JSON `{роль: {id, text}}`;
* `a2/*.a2`: те же предсказания в формате BioNLP-ST (как исходная разметка EPOP), с привязкой к упоминаниям;
* `kg/kg_triples.tsv`, `kg/kg_nodes.json`: фоновый граф знаний, собранный из train+dev, вместе с иерархией мест.

> Формат сабмита Kaggle (`sample_submission.csv`) без авторизации недоступен, поэтому `relations.csv`
> и `events.csv` — «сырые» таблицы графа. Под точные колонки соревнования их переводит небольшая функция
> в `run.py::write_submission`.

## Структура

```
pestkg/
  brat.py       чтение/запись BioNLP-ST (.txt/.a1/.a2), схема ролей
  text.py       токенизация, предложения, ключи узлов
  kg.py         граф знаний: alias-словарь, рёбра отношений, иерархия мест, графовые запросы, экспорт
  resources.py  подграфы GeoNames и NCBI Taxonomy (фильтр по n-граммам корпуса)
  ner.py        словарный NER + entity linking, даты, болезни, аббревиатуры
  relations.py  граф документа, кандидаты, признаки
  events.py     события как клики, признаки клик
  pipeline.py   обучение с кросс-фиттингом, OOF-пороги, предсказание
  evaluate.py   метрики на уровне графа
run.py, download_data.py
```

## Что можно улучшить

* NER: заменить словарь на fine-tuned трансформер (BioBERT/PubMedBERT, нужен GPU). Словарь
  и граф при этом остаются для связывания и как признаки.
* Отношения: добавить LLM-верификатор кандидатов с высоким графовым prior, например «известное ребро,
  но мало текстовых свидетельств».
* Транзитивный вывод по иерархии мест: если вредитель находится в городе, то он находится и в упомянутом регионе
  или стране (нужно проверить, насколько разметка EPOP следует этому правилу).
